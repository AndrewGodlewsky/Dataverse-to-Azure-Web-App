The frame

What never changes

Start with what isn't a choice. A viewer's browser hits an App Service gate; behind it, one container image holds both the React build and the Node backend-for-frontend; the image comes from a registry; the data comes from somewhere. Four edges of that picture are decisions — marked with ◆.

The fork

Live, copy, or both

Every egress option in the atlas is a variation on one of these three shapes. The boxes are identical in all three — only the arrows move. Hybrid is not a compromise between the other two; it is the shape two of the four sample table configurations actually landed on.

The rationale

Why anyone copies at all

Live costs nothing and ships in under a day, so copying only makes sense because of two hard ceilings. Neither is a performance nuisance you can tune around — the first is a shared budget, the second is an error.

Layer — egress

Seven ways out of Dataverse

Two live paths and five copy paths, all ending at the same BFF. Read the annotations as setup · cost · freshness — those three, in that order, are what actually separates them.

Dead paths — they still show up in blog posts

Data Export Service (EOL Nov 2022) · Export to Data Lake (decommissioning from Mar 2025) · OData v2 Organization Data Service (removed — the platform returns an error) · 2011 SOAP endpoint (no Node story) · BYOD (steered away from) · Synapse Link “in-place update” CSV mode (legacy; doesn't scale).

Layer — auth, server side

How the app proves it may read

Four rungs, one base. The base — an app registration with no API permissions, bound to an unlicensed Dataverse application user carrying a read-only role — is identical on every rung; authorization comes from that binding, not from Entra scopes. What changes is only what the app presents to get a token, and whether that thing is a secret someone has to store and rotate.

Layer — auth, viewer side

Whose identity reaches the data

The viewer-side choice looks like a login question but is really a question about throttling and caching. Either the app reads as itself and decides what each viewer may see, or each viewer's own token travels all the way to Dataverse.

Layer — container

Code → image → registry → running app

Two halves that people often merge by mistake: how the image is built and pushed, and how the running app gets it. The second half is pull-based — App Service fetches on restart, using its own identity, and no credential is stored anywhere.

Layer — delivery

What stops being manual

The rungs are additive, not exclusive — starting manual and layering later costs nothing you have to undo. Read each row left to right and ask only one question: which of these steps still needs a person?

Layer — frontend

The interaction that made this a custom app

Cross-filtering is the founding requirement — clicking a bar in one chart re-filters the others. It's why a canned reporting surface was ruled out at framing time, and it's the thing the chart library has to support natively or you hand-roll.

Choosing

Which branch is yours

Four questions against your real tables. They aren't weighted — any single yes on the top pair forces a copy for those queries, and any single yes on the bottom pair forces a live leg. Both kinds of yes together is the hybrid shape.

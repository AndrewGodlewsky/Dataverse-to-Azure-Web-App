The five structural decisions

Each card is one accepted ADR: what was picked, the strongest alternative it beat, and the tradeoff knowingly accepted. Full option fields live on the linked layer pages.

ADR-0001 · Data access Accepted · Med conf

Read Dataverse live via the Web API — no copy store

$0/month, <1 day setup, always-current data. No chart needs a ≥50k-row aggregate and all viewers see all data, which removed every argument for a copy.

Beat: Synapse Link copy (staleness + plumbing for a problem the data doesn't have), hybrid (two query paths, unjustified yet).

Tradeoff: hard platform ceilings — 50k aggregate cap, one shared throttle bucket. All seven egress paths →

ADR-0002 · Auth & identity Accepted · High conf

Stage the server credential: client secret now, federated identity later

A secret gives day-1 laptop connectivity before any Azure exists; the same app registration later trusts the Web App's managed identity and the secret is deleted. Zero rework — the swap is config plus ~10 lines in one module.

Beat: FIC-from-day-1 (blocks first query on Azure infra), managed identity direct (forecloses per-user auth forever).

Tradeoff: a rotating secret exists during stage 1. All three variations →

ADR-0003 · Auth & identity Accepted · High conf

Gate viewers with Easy Auth + an assigned Entra group

The platform gates the site before requests reach the container. Granting access = adding someone to one group. No sign-in code anywhere in the app, and responses stay cacheable because they're never viewer-specific.

Beat: any-tenant-user (contradicts deliberate access), in-app MSAL/OBO (days of plumbing buying nothing under the everyone-sees-everything model).

Tradeoff: all authorization stops at the front door — by design. Viewer options →

ADR-0004 · Hosting Accepted · High conf

One multi-stage image, ACR, managed-identity pull

App Service custom containers expose exactly one HTTP port, so one image (Vite build stage → slim Node runtime serving /api + static) is the natural shape: one deploy unit, one TLS endpoint, no CORS, no registry credentials anywhere.

Beat: separate nginx + Node images (CORS + two apps for an internal tool), ACR admin-account auth (the documented anti-pattern).

Tradeoff: frontend and BFF version together. Tiers, pull auth, CI/CD ladder →

ADR-0005 · Frontend Accepted · Med conf

Vite + Express + Apache ECharts

ECharts is the only library with every needed shape native — including tree/org-chart — and cross-filtering machinery built in (on, dispatchAction, connect). The founding requirement lands on library strength, not hand-rolled state.

Beat: Recharts (no tree series; cross-filtering hand-rolled exactly on the founding requirement), Next.js + visx (SSR buys nothing; week-1 risk), AG Charts (needed shapes paywalled).

Tradeoff: options-object API, largest bundle (managed via modular imports). The full field →

ADR-0006 / 0007 · Process Accepted

How decisions and plans are recorded

0006: hard-to-reverse decisions live as append-only ADRs in plans/architecture/ — never edited, only superseded, so the history of changed direction survives.

0007: large efforts are charted as wayfinder maps on GitHub Issues (map + sub-issues + native dependencies); bulky research stays in-repo under wayfinder/research/. The first map (issue #8) is closed — new efforts chart new maps.

The one tripwire to remember If any chart ever needs an aggregate touching ≥ 50,000 rows, or sustained HTTP 429 throttling appears, add Azure Synapse Link additively — the BFF grows a second read path, nothing is rebuilt — and record it as a superseding ADR. Until then, the copy-store branch stays deliberately unbuilt.
